# MoveWise specification

Phase 1 provides a local relocation workspace with a profile, saved housing options, and budget estimates. Money is INR. Blank amounts are unknown; totals are shown only when every component is known. Deposits are treated as refundable upfront cash, distinct from monthly spending. Commute minutes and links are entered by the user. Sample listings are synthetic and are never presented as live properties.

Future phases will add document questions, specialist agents, plans, coordination, and evaluation. None of those are available in Phase 1.

Phase 2 adds private PDF, TXT, and Markdown uploads, page or section aware ingestion, semantic retrieval, and a bounded Document Agent. Shared demo guides are explicitly synthetic and read-only. The agent may search repeatedly, but only chunks retrieved in that run can become citations. Unsupported questions must state that the documents do not establish an answer. Agreement explanations describe wording without claiming enforceability. Scanned PDFs need OCR outside this phase.

Phase 3 adds a Housing Agent and Planning Agent. Both choose from backend tools within a bounded runtime. The housing comparison is deterministic and uses only saved homes, the profile, and entered budget values. Its score has a maximum of 100 points: monthly affordability 40, upfront affordability 25, commute target 15, and housing preference terms 20. A factor with missing inputs contributes neither points nor possible points; missing information is shown. Monthly and upfront totals are unknown until all components are known. This is a hand-written comparison rule, not trained machine learning.

The Planning Agent proposes a full plan with dated tasks, priorities, categories, assumptions, budget concerns, and citations for document-dependent tasks. A proposal is a preview. Confirmation creates an immutable plan version; cancellation changes no plan. Task completion is stored separately by stable task ID so retained tasks remain complete across revisions. A proposal becomes stale if another version is confirmed or the profile, budget, or selected home changes before confirmation.

Phase 4 adds a Relocation Coordinator that delegates only to relevant existing specialists. A housing request can use Housing alone, an agreement request Document alone, and a combined request multiple specialists. Specialist results retain their IDs, citations, comparisons, proposal previews, statuses, and missing information. Planning can receive prior structured findings, but it still uses its own tools and only proposes changes. The unified Assistant persists conversations and parent/child runs. Its activity timeline shows saved tool and agent status events over SSE, never hidden reasoning. A reconnect resumes event reading; message submission has a workspace-scoped idempotency key.

Phase 5 adds a versioned, small deterministic evaluation dataset and a complete browser walkthrough. The mock provider is explicitly labeled as simulation. Public operation requires OIDC verified identity, HTTPS origins, durable private file storage, workers, upload and request limits, and environment-managed secrets. Development cookies remain available only outside production. Readiness checks database connectivity; operator-managed TLS, monitoring, backups, and external identity configuration are prerequisites for public deployment.
